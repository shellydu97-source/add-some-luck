# 「加点好运」项目交接说明（供 Codex 直接接手）

> 原始交接文件更新时间：2026-07-15  
> 项目性质：本地优先的个人玄学工具  
> 当前进度以仓库中的 `progress.md`、测试报告和 Git 历史为准；本文件负责长期产品原则与冻结边界。

---

## 1. 项目目标

「加点好运」不是一个堆满功能的玄学百科，也不是单纯展示专业术语的排盘工具。

它要解决的核心需求是：

1. 用户建立人物档案并查看八字、星盘。
2. 用户针对一件具体事情进行六爻或塔罗占问。
3. 用户得到普通人能看懂的结果，而不是一大张专业数据表。
4. 用户保存记录，并在未来补充实际结果、验证与备注。
5. 后续可通过 AI、用户自己的 API、本地模型或“一键复制到大模型”获得更深入的个性化解读。

产品应始终遵循：

> 专业计算在底层，普通用户在前台只看到真正需要理解和操作的内容。

> 个人占问与验证工具，命盘作为长期个人底座。

## 4. 产品界面原则

### 4.1 问题输入

- 起卦首页只选择方法。
- 进入具体方法后再输入一次问题。
- 问题可以选填。
- 已输入的问题必须一路保留到结果与记录。
- 新建一次流程时，不应自动带入上一次已经完成的问题。

### 4.2 六爻结果

普通用户默认只需要看到：

1. 自己问的问题
2. 本卦 → 变卦
3. 一句话结果或总体倾向
4. 2～3 个核心判断依据
5. 现实建议
6. 一键复制
7. 查看详细排盘

以下内容默认折叠：

- 原始铜钱
- 6 / 7 / 8 / 9
- 卦辞与全部爻辞
- 纳甲
- 世应
- 六亲
- 六神
- 月建
- 日辰
- 旬空
- 生克关系
- 专业判断依据

“阴面 2 / 阳面 3”是铜钱计分，不应反复占据结果首屏。

无动爻时：

- 只显示一次本卦
- 显示“无动爻，变卦同本卦”
- 不重复显示两个相同卦名

### 4.3 塔罗结果

普通用户默认需要：

1. 原问题
2. 牌阵
3. 综合解读
4. 各路径或各位置的结论
5. 现实建议
6. 一键复制
7. 展开查看单牌详情

单牌关键词、元素、花色、牌义可以保留，但默认折叠。

### 4.4 记录详情

记录默认只展示：

- 原问题
- 当时结果
- 当时综合解读
- 日期
- 验证状态
- 实际结果
- 备注

以下内容默认折叠：

- 原始牌面
- 原始铜钱
- 专业排盘
- 计算快照
- 技术字段
- 完整复制文本

底层数据不要删除，只做界面收起。

### 4.5 面向普通用户的文案

普通用户页面不应出现：

- 演示
- 未接 AI
- 未接算法
- engineVersion
- adapterVersion
- ruleVersion
- 技术详情
- 真实基础计算
- 当前不生成什么功能
- 开发范围说明
- 许可说明
- 测试说明

这些信息只保留在 README、报告、测试、导出 JSON 与代码注释中。

## 5. AI / API 原则

AI 可以负责理解问题与解释结果，但不能参与或修改：

- 抽牌
- 洗牌
- 起卦
- 排盘
- 原始牌面
- 卦象
- 动爻
- 其他不可变结果

AI 输出不得使用绝对成败、恐吓式结论或伪造的精确应期。

---

## 6. Codex 与用户协作规则

### 6.1 用户说“先不要改”

只允许分析、解释、提供方案和列出取舍，不修改代码。

### 6.2 用户要求小范围修改

直接修改，但必须：

1. 开始前备份。
2. 只改指定范围。
3. 不顺手重构其他模块。
4. 不改变已冻结算法。
5. 完成后报告修改内容、文件、build、lint、test 与预览地址。

### 6.3 用户提出产品方向变化

先说明理解、方案、影响、保留、隐藏与延后内容，得到确认后再编码。

### 6.4 用户提供截图

先判断属于 Bug、交互、内容、视觉或算法问题，不要看到截图就重做整页。

### 6.5 禁止主动扩展

不要擅自加入运势、账号、支付、社区、分享、AI、新玄学模块、动效、新依赖或新数据源，除非用户明确要求。

---

## 7. 测试与安全规则

每次改动后至少执行：

```bash
pnpm build
pnpm lint
pnpm test
```

同时检查：

- 390px 无横向溢出
- 浏览器控制台无应用 error / warning
- 刷新后数据保留
- 旧人物与旧记录不丢失
- 塔罗牌序与正逆位不改变
- 六爻原始结果不改变
- 八字与星盘黄金测试无变化

不允许：

- 为了让测试通过而修改黄金期望值
- 用 mock 回退掩盖真实计算错误
- 静默猜测地点、时区、时间
- 删除旧数据
- 修改不可变原始记录
- 在浏览器前端直接暴露 API Key

---

## 8. 视觉设计原则

- 现代、克制、移动端优先。
- 不做廉价紫色星空、满屏金色或传统算命网站风格。
- 保持清晰的信息层级和适度仪式感。
- 普通用户默认看到简洁答案，专业内容可展开。
- 当前已选定的现代视觉系统应保持一致，不随意切换风格。

---

## 9. 最重要的产品原则

> 底层可以复杂，前台必须简单。  
> 数据可以专业，答案必须让普通人看懂。  
> 原始结果必须不可变，解释可以继续升级。  
> 没有接入的功能不要在页面上反复说明。  
> 不要为了显得专业，把用户淹没在术语里。  
> 不要为了显得完整，一次加入太多模块。  
> 每次只解决一个明确问题。
